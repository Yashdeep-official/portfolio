How I work

Based in Calgary but ready to work anywhere.....................................................................................
  1. 01

    Threat model first

    Before writing code, I map assets, entry points and likely attackers, so security decisions shape the architecture instead of patching it later.

    → Data-flow diagram · STRIDE risks
  2. 02

    Build with secure defaults

    Typed APIs, parameterised queries, least-privilege access and strong authentication are the baseline — not optional extras.

    → Clean, reviewed, documented code
  3. 03

    Verify continuously

    Unit and integration tests, static analysis and dependency scanning run in CI on every commit, with manual testing for business-logic flaws.

    → CI pipeline · SAST/DAST reports
  4. 04

    Monitor and respond

    Structured logging, alerting and a clear incident plan mean problems are detected early and handled calmly.

    → Dashboards · Runbooks
